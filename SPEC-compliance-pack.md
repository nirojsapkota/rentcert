# Spec: compliance-pack (Phase 6)

Status: IMPLEMENTED (2026-09-23). Module id: `compliance-pack`. Depends on: `compliance`, `vault`.
Source: PLAN.md sections 11, 16, 17, 41 (scenario 7), 62.

Stack, commands, code style and boundaries from `SPEC-foundation.md` apply unchanged.

---

## Objective

A landlord clicks "Download Compliance Pack" on a property and gets one PDF that summarises the
property's compliance dates, full history and certificate list, ready to send to a tenant, agent
or insurer. The PDF never claims to be a certificate or to prove legal compliance.

## Content (in order)

1. **Cover**: "RentCert Compliance Pack", the property address (street and locality), and
   "Generated: 23 September 2026" (the date in the user's timezone).
2. **Property details**: address, nickname (if any), lease start date (or "Not entered"),
   archived status (if archived).
3. **Compliance summary**: one row per requirement in the property's schedule, showing the
   requirement, last completed, next due, and status label ("Due in 18 days", "Overdue by 3
   days", "Not applicable", "Not set up"). Labels come from the same `buildSchedule()` used by
   the property page. Non-VIC properties show the general-schedule notice. VIC rows show their
   source and "not yet verified" until verified.
4. **Compliance history**: every record, newest completion first: requirement, completed
   ("Last check unknown" where relevant), next due, provider, licence number.
5. **Documents**: one row per document: name, compliance type, completed date of its record,
   upload date, size, and the first 16 characters of its SHA-256. The fingerprint lets a
   recipient confirm that a certificate sent separately is the same file.
6. **Every page**: footer with "Page N of M" and: "Generated by RentCert from information entered
   by the account holder. This document is not a certificate and does not confirm legal
   compliance."

The MVP lists documents but does not merge the original PDFs into the pack (PLAN.md section 16 allows this).

## Design

```text
src/server/compliance-pack/load.ts        loadCompliancePack(userId, propertyId, now) → PackData | null (owner-scoped)
src/server/compliance-pack/generator.ts   new CompliancePackGenerator(data).generate() → Promise<Buffer>
src/app/api/properties/[id]/compliance-pack/route.ts
```

- `CompliancePackGenerator` takes plain data (no database, no request), so tests can render it
  from fixtures. It has no controller logic (PLAN.md section 17).
- `loadCompliancePack` reuses `getPropertySchedule`, `listPropertyHistory` (all pages) and the
  vault queries. It does no status logic of its own.
- PDF library: **PDFKit** (`pdfkit`), as named in PLAN.md. It is listed in
  `serverExternalPackages` so Next.js does not bundle its font data files.
- Font: bundled **Noto Sans** regular and bold (SIL Open Font License, licence file committed in
  `assets/fonts/`). It covers Latin (including Vietnamese), Greek and Cyrillic; the 14 standard PDF
  fonts cannot print many of these. Chinese, Japanese, Korean and other scripts are not covered
  in the MVP (a CJK font adds about 10 MB). Their characters render as blank boxes.
- Route: `GET /api/properties/[id]/compliance-pack`. It checks the session and loads the pack
  owner-scoped. A property that is missing or someone else's returns 404. The response is
  `application/pdf` with `Content-Disposition: attachment; filename="RentCert compliance pack -
  <street> - <YYYY-MM-DD>.pdf"`, `Cache-Control: private, no-store` and `nosniff`.
- The PDF sets metadata: Title "RentCert Compliance Pack – <street>", Creator "RentCert". The
  account holder's email is not included.
- Audit event: `compliance_pack.generated` (metadata: property id only).
- Archived properties can still download a pack (useful as a record when selling or ending a lease).
- A property page with 10 years of history (about 30 records) must still render in under 2 seconds.

## UI

The property page header gets a "Download Compliance Pack" link next to Edit and Archive. It is
a plain link to the route, so the browser downloads the file.

## Testing Strategy

- Unit (generator with fixture data): the output starts with `%PDF-`. Text extraction finds the cover
  title, address, generation date, every summary row, every history row, every document row and
  the footer disclaimer on every page. A long history spans several pages with correct "Page N of
  M". Names in covered scripts ("Nguyễn", "Ελένη", "Иван") come through intact. No text says "compliant" without "not"
  in front, and nothing says "certified" or "guarantee".
- Integration: `loadCompliancePack` returns the right data, uses the user's timezone for the
  date, and returns null for another user's property.
- Route: owner gets 200 with the headers above. Another user, no session and a malformed id get 404.
- End to end (scenario 7): the download is a valid PDF for the correct property, with the correct
  history and generation date.
- Test-only dependency: `pdfjs-dist` (Mozilla PDF.js) as a devDependency, to read text back out
  of generated PDFs.

## Success Criteria

- Scenario 7 passes: valid PDF, correct property, correct history, correct generation date.
- Only the owner can generate a pack.
- Every page carries the "not a certificate" disclaimer.
- lint, typecheck, Vitest, Playwright, build and audit pass.

## Out of scope

Merging original certificates into the pack, branding or custom logos, emailing the pack, and
packs covering several properties.
